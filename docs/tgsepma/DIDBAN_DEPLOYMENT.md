# دیدبان در سایت سپهر مانا

## مسیرها

- صفحهٔ معرفی: `/fa/analysis-and-design` و `/en/analysis-and-design`.
- میزکار مستقل متخصص: `/didban`، با نشست جداگانه از مدیر سایت.
- گزارش مستقل: `/admin/didban`، با همان ورود مدیریت فعلی سایت.
- خروجی کامل: `/api/admin/didban?download=1`، فقط برای مدیر واردشده.

عنوان و خلاصهٔ صفحه از سند منتشرشدهٔ `analysis-and-design` در CMS خوانده می‌شوند. نظرها، تاریخچه، کاربران و فرض‌های تحلیل در CMS ذخیره نمی‌شوند. بانک هنوز پیش‌نویس و کالیبره‌نشده است؛ این میزکار آزمون واقعی کودک نیست.

## استقرار بدون تغییر زیرساخت

Dockerfile دقیقاً به نسخهٔ قبلی سایت بازگردانده شده است. مسیر انتشار موجود را تغییر ندهید. تنها کد پروژه به مخزن Gitea ارسال می‌شود و همان انتشار خودکار فعلی اجرا می‌شود.

Next.js هنگام اولین مراجعه به دیدبان یا گزارش آن، سرویس Python را روی loopback راه‌اندازی می‌کند. `lib/didban-worker.ts` درخواست‌های هم‌زمان را هماهنگ می‌کند و در صورت توقف پردازش، مراجعهٔ بعدی آن را دوباره راه می‌اندازد. وابستگی‌های قفل‌شده همراه کد در `didban/vendor` و با مجوزهای اصلی قرار دارند؛ نصب pip، virtualenv یا بستهٔ سیستمی جدید لازم نیست. Python 3.11+ و SQLite باید در محیط فعلی موجود باشند؛ محیط اصلی قبلی سایت Python را از قبل دارد.

Next.js منابع لازم را در خروجی standalone قرار می‌دهد. این خروجی را با همان `node server.js` قبلی اجرا کنید. مسیر داده به‌صورت پیش‌فرض `data/didban` زیر پوشهٔ کاری سایت است؛ همان فضای دادهٔ فعلی باید پایدار بماند. اطلاعات نظرسنجی در فایل‌های خود باقی می‌مانند. نسخهٔ محلی SQLite و داده‌های runtime وارد Git یا خروجی build نمی‌شوند.

تنظیمات فعلی `ADMIN_PASSWORD`، `ADMIN_SECRET`، `NEXT_PUBLIC_SITE_URL` و تنظیمات CMS حفظ می‌شوند. متغیر جدید اجباری وجود ندارد. برای توسعهٔ محلی می‌توان `WORKBENCH_PYTHON`، `WORKBENCH_PORT` و `WORKBENCH_DATA` را اختیاری تعیین کرد؛ در سرور تغییرشان لازم نیست.

## ساخت سه حساب بدون دسترسی سرور

پس از ورود مدیریت فعلی سایت، درخواست JSON به `POST /api/admin/didban/accounts` بفرستید. بدنه شامل رمزهای `admin`، `test` و `monir.sadat` است و هدر `Origin` باید مبدأ خود سایت باشد. رمزها بین ۸ و ۱۲۸ نویسه‌اند. نقش‌ها و نام‌ها از کد تعیین می‌شوند: مدیر پروژه با دسترسی lead، کاربر تست با برچسب آزمایشی و روان‌شناس «منیرسادات سیدکریمی».

این عملیات افزایشی و تکرارپذیر است؛ حساب موجود یا رمز آن را تغییر نمی‌دهد. پاسخ فقط تعداد حساب‌های ساخته‌شده را برمی‌گرداند. رمز یا هش آن در گزارش، audit یا Git ثبت نمی‌شود. مسیر داخلی ساخت حساب فقط از loopback با امضای جداگانه پذیرفته می‌شود و از پروکسی عمومی مسدود است. فایل seed محرمانه همچنان اختیاری است، اما برای استقرار عادی لازم نیست.

## بررسی پس از انتشار

۱. صفحهٔ معرفی، میزکار و `/didban/api/health` باید پاسخ موفق بدهند.
۲. ورود حساب‌های سه‌گانه، نام روان‌شناس و برنامهٔ شش نمونهٔ فاز اول بررسی شوند.
۳. دادهٔ حساب تست از شاخص‌های واقعی جدا بماند؛ تاریخچه و خروجی کامل ثبت شوند.
۴. گزارش بدون نشست مدیریت 401 باشد؛ مسیرهای internal و ورود سریع محلی از بیرون 404 باشند.
۵. خروجی مدیریت شامل بانک، نظرها، نسخه، تاریخچه، تصمیم‌ها، فعالیت‌ها و دفتر فرض/شاهد باشد و هیچ رمز یا توکنی نداشته باشد.
۶. گزارش نظرسنجی و داده‌های قبلی آن همچنان کار کنند.

در ۱۳ نوامبر ۲۰۲۶، ارسال نخست با کامیت `00f3874` با خطای Build متوقف شد. نسخهٔ آفلاین با کامیت `253b3b3` در همان روز ساعت ۱۷:۴۶ تهران پیام `deployment deployed` گرفت. صفحهٔ معرفی، ورود سه حساب، گزارش مستقل، تاریخچه و جداسازی دادهٔ آزمایشی روی دامنه بررسی شدند. ۲۶ آزمون سرور، ۷ بررسی یکپارچهٔ محلی بستهٔ آفلاین و ۶ دسته بررسی زنده موفق بودند. یک نظر فنی با حساب تست ثبت شده است؛ نظر واقعی متخصص هنوز صفر است. پایداری فضای داده در بازسازی زیرساخت و بازیابی پشتیبان سرور هنوز مستقلاً تأیید نشده‌اند.
