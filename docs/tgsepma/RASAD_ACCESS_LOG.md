# گزارش ورودهای رصد

در داشبورد ۲ با حساب `admin` وارد شوید و گزینهٔ «گزارش ورودها» را بزنید. همین صفحه از منوی پنل مدیر سایت هم قابل دسترسی است. مشاهده‌گر رصد و بازدیدکننده این جدول را نمی‌بینند.

برای رسیدگی به یک مشکل ورود:

1. شناسهٔ پیگیری را از پایین فرم ناموفق بگیرید و در «گزارش ورودها» وارد کنید.
2. «حساب شناخته شد؛ گذرواژه مطابقت نداشت» یعنی درخواست به برنامه رسیده، حساب پیدا شده و مقدار فرستاده شده با تنظیمات فعلی سرور یکی نبوده است. رمز را از کاربر نخواهید؛ بررسی کنید در فرم درست وارد شده، زبان صفحه‌کلید و Caps Lock را بررسی کرده و سپس از مسیر رسمی بازیابی دسترسی پیگیری کنید.
3. «نام کاربری پیدا نشد» یعنی ابتدا نام حساب و مسیر ورود را بررسی کنید. «مبدأ یا فرم نامعتبر» یعنی برنامه پیش از بررسی گذرواژه درخواست را رد کرده است.
4. «اعتبار حساب تأیید شد» یعنی برنامه نشست صادر کرده است. «گزارش باز شد» رکورد جداگانه‌ای است که نشان می‌دهد سرور صفحهٔ اصلی گزارش را برای یک نشست معتبر فرستاده است. اگر شناسهٔ تلاش را ندارید، حساب و زمان تقریبی را کنار هم بررسی کنید. اگر هیچ رکوردی پیدا نشد، ممکن است درخواست به این سرور نرسیده باشد یا رویداد خارج از محدودهٔ نمایش باشد.
5. IP به بررسی کمک می‌کند. ممکن است چند نفر پشت یک IP باشند. برای حساب مشترک `admin` فقط حساب و نشانی ثبت می‌شود؛ نام شخص را باید با حساب‌های شخصی جداگانه مشخص کرد. زمان در صفحه به وقت تهران نمایش داده می‌شود.

زمان دقیق UTC، شناسهٔ تصادفی، حساب، نتیجه، علت، مبدأ ورود (رصد یا پنل سایت) و IP دریافت‌شده به همراه نوع منبع ثبت می‌شود. گذرواژه، بدنهٔ درخواست، توکن یا کوکی نوشته نمی‌شود. نشست رصد از ورود به بخش مدیریت سایت جدا است؛ دو نشست رصد با یک حساب می‌توانند هم‌زمان فعال باشند و خروج یکی، دیگری را نمی‌بندد.

## تنظیم در استقرار

- `ADMIN_PASSWORD` و `ADMIN_SECRET` تنظیمات موجود همان مدیرند. برای استفاده از فرم رصد نام حساب `admin` است.
- فایل‌های روزانه در `data/rasad-audit/` ذخیره می‌شوند. اگر استقرار پوشهٔ اجرا را تعویض می‌کند، `RASAD_AUDIT_DIR` را به یک مسیر مطلق، خارج از `public/` و با مجوز خواندن و نوشتن برای کاربر سرویس اشاره دهید؛ از مسیر موجودی استفاده کنید که بین انتشارها حفظ می‌شود. در چیدمان چند پردازه/سرور، مسیر باید برای همهٔ پردازه‌های نمایش و ثبت مشترک باشد. این صفحه به SQL Server یا سرویس تازه‌ای احتیاج ندارد.
- برای `RASAD_AUDIT_IP_HEADER` تنها نام هدر مخصوصی را قرار دهید که پراکسی مورداعتماد در ورودی آن را بازنویسی می‌کند و سرور برنامه از اینترنت مستقیماً قابل دسترسی نیست. وقتی تنظیمی نداریم، آخرین مقدار معتبر ترجمه‌شده از `X-Forwarded-For` صرفاً به‌عنوان سرنخ نمایش داده می‌شود. اگر مقدار قابل استفاده‌ای استخراج نشود، نشانی «در دسترس نیست».
- پنجرهٔ نگهداری روز جاری UTC و ۲۹ روز قبل است؛ پاک‌سازی فایل‌های قدیمی هنگام ثبت رخداد جدید انجام می‌شود. صفحه آخرین ۲۰۰ تطبیق و حداکثر بخش پایانی هر فایل روزانه را می‌خواند و در صورت محدود شدن نتیجه پیام نشان می‌دهد. در صورت خطای نوشتن، همان اطلاعات محدود در خروجی خطای خصوصی سرویس با نشانگر `[rasad-audit:storage-unavailable]` ثبت می‌شود و لازم است مسیر و مجوزها را بررسی کنید. سیاست نگهداری خروجی خطای سرویس را جداگانه در میزبان تنظیم کنید.

برای آزمون محلی با حساب‌های موقت ابتدا سرویس را اجرا کنید، مقدار `ADMIN_PASSWORD` را در محیط فرآیند آزمون قرار دهید و سپس دستور زیر را اجرا کنید. فایل حساب مشاهده‌گر باید خارج از Git باقی بماند و حاوی `username` و `password` همان محیط آزمون باشد:

```sh
python tests/rasad-auth-smoke.py http://127.0.0.1:3012 /private/viewer.json
```
