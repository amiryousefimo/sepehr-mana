# داشبورد ۲ با Power BI Secure Embed

صفحهٔ `/dashboard_2` مستقل است و از صفحات فارسی و انگلیسی «داشبوردها» لینک دارد. نشانی قبلی `/dashboard_1` به صفحهٔ جدید هدایت می‌شود. پوستهٔ صفحه در سایت باز می‌شود، اما خود گزارش را فقط Power BI پس از ورود حساب سازمانی و بررسی مجوز نمایش می‌دهد. این مسیر از مدیریت سایت، نمونهٔ ساختگی و انبار SQL به‌صورت مستقیم استفاده نمی‌کند.

## تنظیم گزارش

۱. مالک گزارش در **Power BI Service** گزارش موجود را باز کند و از **File → Embed report → Website or portal** نشانی Secure Embed را کپی کند. گزینهٔ **Publish to web** برای این کاربرد مجاز نیست.

۲. در توسعهٔ محلی، در فایل نادیده‌گرفته‌شدهٔ `.env.local` قرار دهید. در استقرار standalone، همین دو مقدار را از کانال متغیرهای محیطی سرویس فعلی Node به فرایند بدهید؛ سپس فرایند را دوباره راه‌اندازی کنید.

```dotenv
POWERBI_EMBED_URL="https://app.powerbi.com/reportEmbed?reportId=aaaaaaaa-0000-1111-2222-bbbbbbbbbbbb&autoAuth=true"
POWERBI_REPORT_TITLE="رصد ۱"
```

شناسهٔ بالا نمونه است. برای گزارش واقعی، کل URL رسمی را جایگزین کنید. عنوان اختیاری است. URL در مرورگر قابل مشاهده است و توکن، رمز، مجوز یا محدودیت دسترسی نیست. لینک دارای توکن، میزبان غیر از `app.powerbi.com`، نشانی HTTP و مسیرهای عمومی مانند `/view` پذیرفته نمی‌شوند. نبود یا نامعتبر بودن تنظیم باعث نمایش پیام راه‌اندازی می‌شود و iframe ساخته نمی‌شود.

## استقرار بدون Docker

اگر مخزن به انتشار خودکار سایت متصل است، کد را به شاخهٔ انتشار همان مخزن ارسال کنید و تنظیمات را از کانال فعلی سرویس وارد کنید. Dockerfile یا زیرساخت موجود نیازی به تغییر ندارد. اگر انتشار دستی از SSH انجام می‌شود، با حساب استقرار مجاز در پوشهٔ انتشار پروژه، پس از دریافت نسخهٔ تأییدشده:

```sh
npm ci
npm run build
cp -a .next/static .next/standalone/.next/
cp -a public .next/standalone/
```

فرایند فعلی سایت را با همان مدیر سرویس، متغیرها، کاربر، مسیر پایدار داده و پراکسی فعلی روی خروجی جدید اجرا کنید. نقطهٔ ورود `node .next/standalone/server.js` است؛ نمونهٔ زیر فقط برای فرایند آزمایشی جداگانه است:

```sh
HOSTNAME=127.0.0.1 PORT=3001 node .next/standalone/server.js
```

پس از سلامت مسیر و ورود آزمایشی، انتشار را طبق رویهٔ سرویس فعال کنید. برای بازگشت، خروجی قبلی را با همان مدیر سرویس فعال کنید. این صفحه به Redis، SQL یا سرویس دیگری در Next.js نیاز ندارد. نوع اتصال و به‌روزرسانی دادهٔ مدل موجود، از جمله DirectQuery یا Gateway در صورت استفاده، در Power BI باقی می‌ماند.

## کنترل دسترسی و سازگاری

- در نشست خصوصی و بدون ورود، پوستهٔ سایت باز می‌شود ولی داده نباید نمایش داده شود. سپس با حساب مجاز وارد شوید و بازشدن گزارش، فیلترها و تمام‌صفحه را در دسکتاپ و موبایل بررسی کنید.
- با حسابی که مجوز مشاهده ندارد همین مسیر و لینک مستقیم را باز کنید؛ Power BI نباید داده نشان دهد. اگر گزارش RLS دارد، با دو هویت متعلق به نقش‌های متفاوت دامنهٔ داده را جداگانه بررسی کنید.
- در `curl -I https://tgsepma.com/dashboard_2` وجود `Cache-Control: private, no-store` و سیاست `frame-src` را بررسی کنید. برای نشانی قبلی، پاسخ `308` به مسیر جدید را بررسی کنید. در پراکسی، `Cross-Origin-Opener-Policy: same-origin` یا سیاست متعارض `frame-src` نباید پنجرهٔ ورود و iframe را مسدود کند. برای عیب‌یابی، ابتدا لینک «ورود و بازکردن در Power BI» را در تب تازه امتحان کنید.
- با URL خالی یا لینک عمومی `/view` صفحه نباید iframe بسازد. با URL رسمی، یک بارگذاری اولیه انجام می‌شود. در صورت کندی، تلاش دوباره فقط با اقدام کاربر iframe را بازنشانی می‌کند.

Power BI در مبدأ جداگانه اجرا می‌شود؛ صفحهٔ سایت نمی‌تواند از رویداد بارگذاری iframe تشخیص دهد که کاربر وارد شده یا مجوز مشاهده دارد. خطاهای ورود و دسترسی داخل Power BI نمایش داده می‌شوند. بعضی مرورگرهای مبتنی بر Chromium ممکن است ورود دوباره بخواهند و مسدودبودن پنجرهٔ ورود می‌تواند از ورود در iframe جلوگیری کند. هر بیننده باید Pro یا PPU داشته باشد، مگر اینکه گزارش و مدل معنایی روی ظرفیت واجد شرایط Premium یا Fabric F64 به بالا باشند. [راهنمای رسمی Secure Embed مایکروسافت](https://learn.microsoft.com/en-us/power-bi/collaborate-share/service-embed-secure).
